# AI-PhD SKILL 之 RL 101：从一个 Loss 看懂 PPO 和 GRPO

[← 返回目录 / Index](../../README.md) · 中文原文 · [English](7-RL101-EN.md)

今天来讲讲 RL。这个话题，我一直处在一种很微妙的状态：know-what，但是不太 know-why，更谈不上 know-how。

最近在秋招，很多团队都要招“懂 RL”的人。但我越来越觉得，“懂 RL”至少可以分成四个 level。

Level 0：能默写 GRPO 公式，知道怎么调框架把训练跑起来。

Level 1：能看懂公式里的每一项。知道 $\pi_{\mathrm{old}}$、$\pi_\theta$、$\pi_{\mathrm{ref}}$ 分别是谁，为什么要算 ratio，为什么要 clip，GRPO 相比 PPO 去掉了什么。

Level 2：能从目标函数一路推到 Policy Gradient、baseline、critic、TD、GAE、PPO 和 GRPO，知道每引入一个概念，到底是在修补前一个 loss 的什么问题。

Level 3：能看懂一个完整 RL 系统为什么 work，也能诊断它为什么不 work。问题可能不在最终公式，而在 task、rollout、verifier、advantage、sampling、loss reduction、truncation、exploration 或 held-out evaluation。到了这一层，才能真正解释 DAPO 为什么要做 Dynamic Sampling、Clip-Higher、Token-Level Loss 和 Overlong Reward Shaping，而不是把它们当成四个新的名词继续背。

在很长一段时间里，我都停留在 Level 1。GRPO 的公式见过很多次，每个符号也大概认识。但只要继续追问：advantage 为什么这样算？为什么需要 critic？GAE 到底填在 PPO 的哪个位置？clip 为什么能让同一批数据多训练几次？我就只能打个马虎眼过去。

所以，我想从头整理一次。

如果你：

- 知道 GRPO 大概是什么；
- 懂 LLM、log-probability 和梯度下降；
- 想对 RL 建立一个系统、相对扎实的认识，从 Policy Gradient 到 TD/GAE，顺带理解 Markov 性质，再到 PPO、GRPO 和 DAPO；
- 不想一上来就被几十页公式劝退；

那这篇帖子应该比较适合你。

如果你是数学大师、RL 大师，或者对概率、梯度和 LLM 训练完全没有概念，这篇可能不会特别对胃口。

## 1、我们到底想优化什么？

以 LLM RL for Math 为例。

给模型一个数学题 $x$，模型 rollout 出一条回答 $y$，verifier 检查答案并给出最终奖励 $R(x,y)$。先做最简单的设定：答对得 1 分，答错得 0 分，生成中间没有奖励，取 $\gamma=1$。

我们的目标是：

$$
\max_\theta J(\theta)
=
\mathbb E_{x\sim\mathcal D,\;y\sim\pi_\theta(\cdot\mid x)}
[R(x,y)].
$$

翻译成人话，就是让模型未来生成的回答平均得分更高。

如果把整条回答看成一个 action，这就是一个 contextual bandit：输入 prompt，采样 response，得到一次 reward。

但 LLM 并不是一次吐出整条回答。它每次生成一个 token：

$$
\pi_\theta(y\mid x)
=
\prod_t \pi_\theta(a_t\mid s_t),
\qquad
s_t=(x,y_{<t}),\quad a_t=y_t.
$$

所以，同一个问题也可以被展开成一个 token-level decision process：当前状态是“题目 + 已生成前缀”，action 是下一个 token。

接下来的所有东西，本质上都在解决同一个问题：

【怎么把最终的一个 verifier reward，变成能够更新每个 token probability 的 loss？】

## 2、Reward 不可微，为什么还能训练 LLM？

verifier 只返回 0 或 1。它通常不可微，也没有办法告诉模型是哪一步推理出了问题。

但是，模型生成这条回答的概率是可微的。

Policy Gradient 使用一个很简单的关系，把 reward 接到 log-probability 的梯度上：

$$
\nabla_\theta J(\theta)
=
\mathbb E\left[
R(x,y)\nabla_\theta\log\pi_\theta(y\mid x)
\right]
=
\mathbb E\left[
\sum_t R(x,y)\nabla_\theta\log\pi_\theta(a_t\mid s_t)
\right].
$$

因此，我们可以构造一个 sampled surrogate loss：

$$
\mathcal L_{\mathrm{PG}}(\theta)
=
-\widehat{\mathbb E}
\left[
\sum_t w_t\log\pi_\theta(a_t\mid s_t)
\right].
$$

计算 actor gradient 时，采样得到的 token 和权重 $w_t$ 都被当作固定数据，不对 reward 和 sampling 过程求导。

最简单的选择就是 $w_t=R(x,y)$。

答对的回答中，所有 sampled tokens 的 log-probability 都会被提高。答错得 0 分时，这条回答本身没有直接梯度；如果 reward 可以为负，低奖励轨迹也可以被直接抑制。

这就是 REINFORCE。

到这里，我们已经有了一个真正可以训练 LLM 的 RL 算法。它可能方差很大、样本效率很低、credit assignment 很粗糙，但它已经成立。

所以 RL 的起点并不神秘：

【采样一条轨迹，用它拿到的 reward 加权这条轨迹的 log-probability】

但现在还有一个问题。假设一道很难的题答对得 1 分，一道送分题答对也得 1 分，这两个 1 分应该产生完全一样的更新强度吗？

## 3、从绝对分数到“比预期好多少”

直接使用 reward，只知道“这次拿了多少分”。我们更想知道：

【从当前前缀出发，这次结果比原本预期好多少？】

于是引入 baseline：

$$
\hat A_t^{\mathrm{MC}}
=
G_t-b(s_t).
$$

其中，$G_t$ 是从当前 token 往后实际得到的累计回报。在本文只有终局奖励且 $\gamma=1$ 的设定下，每个生成 token 对应的 $G_t$ 都是最终的 $R$。

例如，这次答对拿到 1 分，但从这个前缀继续生成，原本只有 0.6 的预期得分，那么更新权重就是 $1-0.6=0.4$。

如果一次 rollout 只拿到 0 分，但原本预期能拿 0.6 分，那么权重就是 $-0.6$。模型会降低这条 sampled trajectory 的概率。

只要 baseline 在给定 $s_t$ 后不依赖当前 action $a_t$，并且在 actor loss 中 stop-gradient，它就不会改变 Policy Gradient 的期望：

$$
\mathbb E_{a_t\sim\pi(\cdot\mid s_t)}
\left[
b(s_t)\nabla\log\pi(a_t\mid s_t)
\right]
=0.
$$

baseline 不需要完美，甚至不一定需要是一个神经网络。它可以是常数、batch reward mean，也可以是同一个 prompt 下、不包含当前回答的其他回答的平均 reward。

但如果希望 baseline 能根据“题目 + 当前前缀”动态变化，我们可以训练一个 critic：

$$
V_\phi(s_t)
\approx
V^\pi(s_t)
=
\mathbb E_\pi[G_t\mid s_t].
$$

它回答的问题是：

【从这个前缀继续按当前策略生成，预计最后能拿多少分？】

最直接的训练方式，是把真实 rollout return $G_t$ 当作 label，让 $V_\phi(s_t)\longrightarrow G_t$。

于是，我们有了两个学习任务：

- actor 学的是下一 token 的概率分布，目标是提高未来 reward；
- critic 学的是当前前缀的预期回报，目标是给 actor 提供更好的比较基准。

这里有一个很重要的边界：

【在 $G_t-V_\phi(s_t)$ 中，critic 不准确主要影响方差，不会让 Policy Gradient 因此变成有偏；真正开始依赖 critic 准确性的地方，是 bootstrap。】

## 4、为什么会出现 Bellman、TD 和 GAE？

用完整的最终结果训练 critic，当然可以。但一条回答可能有几千甚至几万 token，只有生成结束时才知道 reward。这样的监督很稀疏，方差也很大。

我们希望利用一个更局部的关系：当前前缀值多少，可以由“这一步拿到的 reward + 下一个前缀值多少”来估计。

要做到这一点，当前 state 必须足以描述未来的 transition 和 reward 分布。这就是 Markov 性质：未来给定当前 state 和 action 后，不应该再依赖更早但没有包含在 state 里的历史。

Markov 并不意味着一定要保存完整历史，只需要 state 是历史关于未来的充分统计量。对纯文本生成来说，把 prompt 和完整生成前缀放进 $s_t$，是最自然的做法。

有了这个前提，就可以写出 Bellman expectation equation：

$$
V^\pi(s_t)
=
\mathbb E_\pi
\left[
r_t+V^\pi(s_{t+1})\mid s_t
\right].
$$

把等式右边当作“看完这一步后的新估计”，再减去原本的估计，就得到 TD error：

$$
\delta_t
=
r_t+V_\phi(s_{t+1})-V_\phi(s_t).
$$

在只有终局 reward 的 LLM 生成中，这个式子非常直观：

- 非终局 token 的 $r_t=0$，所以 $\delta_t=V(s_{t+1})-V(s_t)$；
- 最后一步拿到 reward，并令 terminal state 的 value 为 0，所以 $\delta_t=R-V(s_t)$。

也就是说，对中间 token，TD 在问：

【生成这个 token 之后，critic 认为最终答对的概率上升了还是下降了？】

如果 $V_\phi=V^\pi$，那么在给定 $s_t,a_t$ 后，$\delta_t$ 的条件期望就是真实 advantage，即 $\mathbb E[\delta_t\mid s_t,a_t]=A^\pi(s_t,a_t)$。

但真实训练里的 critic 不可能一直完美。与 state-only baseline 不同，$V(s_{t+1})$ 会通过 next state 依赖当前 action，因此它的预测误差不会自动抵消。TD 用更低的方差换来了 critic approximation bias。

现在我们有两个极端：

- Monte Carlo：一直等到 episode 结束，使用真实 $G_t-V(s_t)$。它没有 bootstrap bias，但方差大；
- one-step TD：只看一步真实 reward，然后立刻 bootstrap 到 $V(s_{t+1})$。方差小，但更依赖 critic。

GAE 做的事情，就是在这两个极端之间折中：

$$
\hat A_t^{\mathrm{GAE}}
=
\delta_t
+\lambda\delta_{t+1}
+\lambda^2\delta_{t+2}
+\cdots.
$$

这里仍然取 $\gamma=1$。一般形式的系数是 $(\gamma\lambda)^l$。

- $\lambda=0$：退化成 one-step TD；
- $\lambda=1$：如果拿到了完整 episode，并正确令 terminal value 为 0，望远镜求和后回到 $G_t-V(s_t)$；
- $0<\lambda<1$：混合不同长度的真实 reward 和 bootstrap prediction。

因此，$\lambda=1$ 时，即使 critic 不完美，也会重新退化成 Monte Carlo return 减去一个 state-only baseline；$\lambda<1$ 时，critic error 才会通过 bootstrap 留在 advantage estimate 中。

因此，GAE 在整个训练系统里填补的位置非常具体：

【它负责计算 actor loss 中每个 token 的更新权重 $\hat A_t$】

到这里，advantage 已经有了。但我们仍然只能比较放心地在这批 rollout 上更新一次。为什么？

## 5、为什么还需要 PPO？

假设这批回答来自策略 $\pi_{\mathrm{old}}$。第一次更新前，当前策略 $\pi_\theta$ 和它相同。

更新几步以后，$\pi_\theta$ 已经变了，但数据仍然来自旧策略。如果继续把同一批数据当成“当前策略刚刚生成的数据”反复训练，更新可能越来越激进。

PPO 先记录 rollout policy 生成每个 token 时的 old log-probability，然后计算当前策略和旧策略的概率比：

$$
\rho_t(\theta)
=
\frac{\pi_\theta(a_t\mid s_t)}
{\pi_{\mathrm{old}}(a_t\mid s_t)}
=
\exp(
\texttt{new\_logprob}_t-
\texttt{old\_logprob}_t
).
$$

PPO-Clip 的 actor loss 是：

$$
\mathcal L_{\mathrm{PPO}}(\theta)
=
-\widehat{\mathbb E}_t
\left[
\min\left(
\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t
\right)
\right].
$$

先不看整个公式，只看它在做什么。

如果 $\hat A_t>0$，说明 sampled token 比预期好，我们希望提高它的概率。但当 ratio 已经超过 $1+\epsilon$ 时，继续提高不再获得额外奖励。

如果 $\hat A_t<0$，说明 sampled token 比预期差，我们希望降低它的概率。但当 ratio 已经低于 $1-\epsilon$ 时，继续降低也不再获得额外奖励。

所以 clip 做的不是强行把所有 ratio 锁在区间里，而是：

【取消沿着“改善 surrogate objective 的方向”走得过远时的额外激励】

如果参数共享、不同 token 的梯度相互影响，某些 ratio 依然可能跑出 clip 区间。PPO 也不保证真实 reward 单调提高。它只是提供了一个相对保守的 local surrogate，让我们能够在同一批 rollout 上做多轮 minibatch update。

一个 PPO iteration 中，下面这些东西应该保持固定：

- 生成这批数据的 $\pi_{\mathrm{old}}$；
- rollout 时记录的 `old_logprobs`；
- rollout-time critic value；
- 根据这批数据一次性算出的 advantage 和 value target。

训练过程中，只有当前 actor $\pi_\theta$ 和当前 critic $V_\phi$ 在变化。完成若干个 PPO epochs 后，再用更新后的 actor 采样下一批回答。

这里还要区分另一个常见符号：$\pi_{\mathrm{ref}}$。

- $\pi_{\mathrm{old}}$ 是生成当前 batch 的 rollout policy snapshot，下一轮会刷新；
- $\pi_{\mathrm{ref}}$ 是用于 KL regularization 的 anchor，在一个优化阶段内保持固定；常见实现取初始/SFT model，也有算法按外层 iteration 刷新；
- PPO ratio 的分母是 $\pi_{\mathrm{old}}$，不是 $\pi_{\mathrm{ref}}$。

现在我们终于可以用一句话区分 GAE 和 PPO：

【GAE 决定 advantage 怎么估；PPO 决定如何拿着这批固定 advantage 更新 policy】

## 6、从 PPO 到 GRPO

PPO 很好，但 critic 也很贵。

对于 LLM，critic 往往和 actor 体量相近，至少也需要额外的 value head、activation、optimizer state 和训练计算。而且长 CoT 下，value learning 本身可能不稳定。

能不能不训练 critic？

Group Relative Policy Optimization，也就是 GRPO，核心思路是：对于同一个 prompt，一次采样一组回答，用组内回答的相对 reward 构造更新权重。

假设对题目 $x$ 采样 $G$ 条回答，得到奖励 $R_1,\ldots,R_G$，第 $i$ 条回答的 group-relative advantage 可以写成：

$$
\hat A_i
=
\frac{R_i-\operatorname{mean}(R_1,\ldots,R_G)}
{\operatorname{std}(R_1,\ldots,R_G)}.
$$

一条回答比同组平均水平好，advantage 为正；比平均水平差，advantage 为负。然后把这条 sequence-level advantage broadcast 给回答中的 token，再放进 PPO-style ratio 和 clip objective。

所以，从这条路线看：

- PPO 通常用 learned critic 和 GAE 得到 token-level $\hat A_t$；
- GRPO 用同一个 prompt 下多条回答的相对 reward 得到 $\hat A_i$；
- ratio、clip 和 old policy 这些 PPO-style 更新机制仍然保留；
- critic 和 GAE 不再是必需组件。

原始 GRPO objective 还直接加入了当前 policy 相对 $\pi_{\mathrm{ref}}$ 的 KL penalty。这条 KL 约束与 group-relative advantage 是两个不同维度的设计：$\pi_{\mathrm{ref}}$ 负责限制 policy 漂移，$\pi_{\mathrm{old}}$ 才是 importance ratio 的分母。

GRPO 的好处不只是省掉 critic。同一道题内部比较，也自然消除了一部分题目难度差异：一道难题偶尔出现一条正确回答，这条回答会比同组错误回答得到明显更高的权重。

但 GRPO 也没有凭空解决所有问题。

- 每个 prompt 要采样多条回答，rollout 成本不低；
- 如果一组回答全部正确或全部错误，组内 reward 没有方差；经过常见的数值安全处理后，这组 advantage 为 0，无法提供有效 policy gradient；
- sequence reward 被 broadcast 给所有 token，仍然无法精确指出究竟哪一步推理产生了价值；
- 训练效果仍然高度依赖 verifier、sampling distribution、长度处理和 loss reduction。

所以 GRPO 不是“PPO 的全面升级版”。更准确地说，它替换了 PPO 中 advantage estimation 的一条具体路线。

## 7、为什么理解这些以后，DAPO 就不再神秘？

Decoupled Clip and Dynamic Sampling Policy Optimization，也就是 DAPO，最值得学习的地方，不是它又发明了一个更长的 loss，而是它从实际训练失败出发，修改了 RL pipeline 中四个不同位置。

第一，Clip-Higher 修 exploration。

标准 PPO 通常使用对称区间 $[1-\epsilon,1+\epsilon]$。对于 positive-advantage 的低概率 token，相同的 ratio ceiling 对应的绝对概率增量很小，很容易过早停止继续提升。DAPO 把 lower clip 和 higher clip 解耦，给正向提升留下更大的上界。论文中的经验解释是，这有助于保留低概率 exploration tokens，缓解其训练设置下的 entropy collapse。

这不是“clip 越大越好”的普遍定理。clip 太宽同样可能让更新失稳。它表达的是：稳定性和 exploration 之间存在 trade-off，而且上下两个方向不一定应该使用完全对称的约束。

第二，Dynamic Sampling 修 effective batch。

GRPO 依赖组内相对 reward。如果一个 prompt 的所有回答都对，或者所有回答都错，标准差为 0，这组数据无法提供 group-relative gradient。

DAPO 持续采样并过滤这些零梯度组，直到 batch 中装满同时包含正确和错误回答的有效 prompts。这样做增加了 rollout，但减少了 optimizer 每一步看到的无效样本，使 effective batch size 更稳定。

它本质上也改变了训练 prompt distribution：模型会更集中地学习当前能力边界附近的题目。因此，Dynamic Sampling 可以理解成一种随策略变化的 curriculum，而不只是一个工程加速技巧。

第三，Token-Level Policy Gradient Loss 修 loss reduction。

原始 GRPO 常见的 reduction 是：先在每条回答内部对 token loss 求平均，再对回答求平均。这样每条回答权重相同，于是一条很长回答中的单个 token，权重会比短回答中的 token 更小。

DAPO 改成在整个 batch 的有效 response tokens 上统一求平均。这样每个 token 的权重更一致，长而高质量的 reasoning tokens 不会被过度稀释，长而低质量、重复或乱码的回答也会受到更充分的惩罚。

这看起来只是一个 `mean` 放在哪里的问题，但它实际改变了不同 sequence length 在优化目标中的权重。

第四，Overlong Reward Shaping 修 truncation noise。

一条回答因为真的不会做而答错，和一条回答因为刚好超过 max length、被系统截断而拿到 0 分，不完全是同一件事。如果全部粗暴记成相同的失败 reward，模型看到的监督会有噪声。

DAPO 先观察到过滤 truncated samples 能提高稳定性，随后使用靠近长度上限时逐渐增加的 soft penalty，让模型在撞上 hard truncation 之前就收到连续反馈。

所以 DAPO 为什么能 work？至少按照论文给出的实验和解释，不是因为某一个神奇公式，而是因为四个改动分别对准了四种真实训练 pathology：

- exploration 被过早压缩；
- batch 里有效 group 越来越少；
- 长短回答在 loss reduction 中权重失衡；
- hard truncation 制造 noisy reward。

这就是我理解的 Level 3：不只问“公式是什么”，而是问【训练信号在哪里消失、在哪里失真、在哪里被错误加权】。

## 8、最后，把整条链串起来

现在回头看，所有概念都在填补上一个 loss 留下的缺口。

我们想用最终 reward 更新 LLM 参数，所以引入 Policy Gradient。

原始 REINFORCE 的绝对 reward 方差太大，所以引入 baseline 和 advantage。

我们希望 baseline 随前缀变化，所以训练 critic 预测 $V(s_t)$。

完整 Monte Carlo return 太晚、方差太大，所以利用 Markov 性质和 Bellman equation 做 TD bootstrap。

one-step TD 太依赖 critic，Monte Carlo 方差又高，所以用 GAE 混合不同步数的估计。

同一批 rollout 直接反复更新容易走得太远，所以 PPO 用 old-policy ratio 和 clip 构造 local surrogate。

LLM critic 太贵，也不一定好学，所以 GRPO 用同 prompt 多回答的 group-relative reward 替代 learned value baseline。

GRPO 真正规模化训练时又暴露出 exploration、有效采样、长度权重和 truncation noise，所以 DAPO 分别修改 clip、sampling、loss reduction 和 reward shaping。

最后可以压缩成六句话：

【Policy Gradient 解决 reward 如何变成 gradient】

【baseline 解决更新信号如何变得可比较】

【critic、TD 和 GAE 解决 advantage 如何估计】

【PPO 解决同一批 advantage 如何被相对稳健地重复利用】

【GRPO 解决不用 critic 时，baseline 从哪里来】

【DAPO 解决这些算法进入长 CoT 大规模训练后，真实系统为什么仍然会失效】

真正理解 RL，不是能默写越来越长的公式，而是从目标函数出发，知道每一个 estimator、ratio、clip、mask 和 reduction 在解决什么问题，又引入了什么新的 trade-off。

我现在也远远谈不上 RL 大师。但至少下一次再看到一个新的 RL algorithm 时，我希望自己不只是问：

它的公式和 GRPO 有什么不同？

而是能继续问：

它改了哪一个训练信号？

它降低了什么 bias 或 variance？

它改变了哪些样本的权重？

它修复了哪个 failure mode？

以及，它是否真的在 held-out evaluation 上，让模型学到了我们想要的能力？
