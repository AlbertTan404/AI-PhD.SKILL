# AI-PhD SKILL 之 AI 论文的storytelling

[← 返回目录 / Index](../../README.md) · 中文原文 · [English](0.1-Story-Telling-EN.md)

我先简单地把storytelling划分两个方向:solid和novel。
Solid:让读者感到“原来如此!
白天走路，有经验的人会告诉你:避开路面反光的地方，那下面多半是水坑。这个经验很solid，直到有一天你夜里出门，发现这招完全失效了--你精准地踩进了每一个水坑。
这时候如果你交一篇论文说"我们提出了夜间避坑新算法，实验表明准确率提升15%"，审稿人只会翻白眼。因为你还没回答那个最要命的问题:为什么白天work的方法晚上不work了?
真正solid的做法是蹲下来看光。你发现白天太阳在头顶，水面像镜子一样把光直接反射进你眼睛，所以水面比路面亮;但晚上环境光微弱，路面粗糙形成漫反射，反而比镜面般的水坑更亮。原来如此!白天走暗，晚上走亮。
到这一步，你的motivation才算立住。接下来方法几乎是水到渠成的:针对"夜间路面-水坑反射模型反转"这一现象，提出自适应阈值/双模态判断，实验里不光要证明"我们比baseline高几个点"，更要证明"在夜间反射混淆场景下，之前的方法确实失效了，而我们的方法在这个场景下消除了之前的错误"。
这种论文的快感在于:审稿人读完introduction，会有种被点醒的感觉一"原来之前的方法不work，rootcause是这个!"
Novel:让读者感到“还能这样!
但还有一种更狠的写法:你根本不讨论怎么在夜里分辨水坑，你直接说"我们发明了雨鞋"。
这就是novel。审稿人的第一反应不是"原来如此"，而是"原来还能这样?!"你改变的不是解法，而是问题的预设前提一为什么一定要避坑?为什么不能让坑失去意义?
这种故事的难度远高于前者。因为solid型论文的敌人是"逻辑漏洞"，而novel型论文的敌人是"必要性"。你必须在很短的篇幅里证明:雨鞋不仅存在，而且比练出一双夜视眼更根本、更通用、更优雅。一旦审稿人觉得"雨鞋太重了/雨鞋只能走浅水/大部分人还是只想练夜视眼"，就很被动了。
所以novel型论文的introduction不能只是介绍雨鞋的材质，必须讲清楚:为什么footwear这个维度之前被忽视了?是什么技术突破让雨鞋现在变得可行?穿上雨鞋之后，"避坑"这个子问题是不是就自动消失了?
